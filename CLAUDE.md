# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Translator: настольное приложение на Tauri 2 (Rust) и Svelte 5 для перевода игр на русский, с графом сцен, глоссарием и LLM: локальными (LM Studio, Ollama) и внешними (ChatGPT, Claude, Gemini). Сейчас поддерживается Ren'Py, другие движки подключаются через трейт `GameEngine`.

## Состояние

Идёт переход на 2.0: проект один раз считывает игру и дальше работает со своей копией в SQLite. Код 1.0 в Rust удалён. Готовы хранилище, проекты, ключи API, считывание Ren'Py и настройки LLM. Окно 2.0 пока состоит из стартового экрана (`src/lib/StartScreen.svelte`: список проектов, создание по папке игры, открытие, архив, удаление), таблицы перевода (`src/lib/Workspace.svelte`: слева плоский список сцен по алфавиту оригинального имени (перевод названия, под ним оригинал) с поиском и процентом (`src/lib/scene-tree.ts`, команда `translation_scenes`), реплики вне сцен пунктом «Без сцены · файл» (`ScopeDto::Loose`); у открытой сцены шапка и панель действий с репликами сцены (`scene_lines`), между списком и репликами всегда открытая панель описания `src/lib/SceneCard.svelte` со слайдером числа частей (`describe_scene` с `parts`), правка с историей в `revisions`, подтверждение черновиков модели; вид «Граф» в `src/lib/SceneGraph.svelte` показывает сцену с входами и выходами, раскладка в `src/lib/scene-graph.ts`) и окна настроек моделей (`src/lib/LlmSettings.svelte`: провайдеры с ключами и списком моделей, профили и их порядок, настройки действий; справочник видов провайдеров в `src/lib/llm-catalog.ts`). `src/routes/+page.svelte` переключает экраны и открывает настройки с обоих. Перевод и редактура моделью работают из таблицы (кнопки файла и сцены, прогресс через `Channel`, ход любого запуска модели и остановка в общей полосе под шапкой `src/lib/RunBar.svelte`, реестр текущего запуска `src/lib/run-status.svelte.ts`; меню «Запуски» и баннер итога откатывают запуск по `revisions`, «Очистить» очищает файл или сцену): `LlmClient::send`, `LlmRun`, `TranslationService`, ядро в `translation/` (`batcher`, `prompt`, `answer`, `text`, `hints`). Вид «Глоссарий» (`src/lib/Glossary.svelte` и `Glossary*.svelte`) разбирает говорящих, правит персонажей, термины и токены без модели (`glossary/`: репозитории, `GlossaryService`, команды); перевод берёт из него имена, род, термины и значения токенов. Модель предлагает перевод терминов, подписей говорящих и значения токенов (`glossary/suggest.rs`) и написание имён, фамилий и форм персонажей (`glossary/names.rs`: разбор происхождения в `name_origins`, правила языков из `name_rules/`, перевод, проверка), всё через `NamesService`. Окно показывает отбор (`src/lib/suggest-run.svelte.ts`), а отмеченное пишут обычные команды правки. Раздел «Правила имён» правит общие правила и свои правила проекта и просит у модели черновик. Перевод реплик получает правила языков упомянутых в пакете имён. Панель описания сцены в таблице правит название и описание и описывает сцену моделью по выбранному слайдером числу частей: `DescribeService` режет сцену на части (`glossary/parts.rs`), пишет заметку каждой части в `notes`, собирает описание и название (`glossary/describe_prompt.rs`); запуск из карточки заменяет описание, группа идёт с глубиной чтения `ReadingDepth`. Перед описанием сцены запуск её разбирает (действие `analysis`, `glossary/analyze.rs`): модель по частям находит новых персонажей и термины, они сразу пишутся в глоссарий без отбора (другое имя известной записи, по `same_as` модели или аббревиатура по первым буквам, «PPF» у «People's Police Force», ложится формой той записи; если связь нашлась позже, две записи сливаются: `merge_terms`, `merge_characters`, `give_term` в `glossary/service.rs`), затем персонажи и термины сцены без описания описываются, и только потом сама сцена. Под описанием карточка показывает персонажей и термины сцены (команда `scene_entries`). Перевод сцены без описания начинается с её чтения тем же путём (`SceneReader`, запросы через трейт `Ask` в запуске перевода): описание пишется только в пустое поле и сразу идёт в запросы перевода. Персонажи и термины описываются тем же путём (`glossary/entries.rs`: их сцены по говорящим и упоминаниям, части из целых сцен через `---`); блок «Описание по сценам» в их карточках (`src/lib/DescribeParts.svelte`) запускает описание, показывает части с заметками и исключает заметки и сцены. Кнопка «Мод» в шапке таблицы (`src/lib/ModPanel.svelte`) собирает `ru_lang.rpa` в папке проекта без папки игры, ставит его в привязанную игру и снимает: `ExportService` (`export/`: вход мода из project.db, перевод подписей говорящих `SpeakerLabels`) и `engines/renpy/modpack.rs` (правка файлов `tl/russian` по `target_lines` и компиляция, строковый перевод для игры без перевода, переключатель языка, готовая копия `.rpyc` игры для файла, который компилятор мода не знает). Кнопка «Версия игры» в шапке таблицы (`src/lib/ScanPanel.svelte`) считывает игру заново, меняет папку игры и показывает «Пропавшие» с привязкой перевода к реплике: `ScanService` (`scan/`: сопоставление реплик в `matching.rs`, запись снимка с переносом перевода в `ScanRepo::apply`), `ProjectService::rebind`; при открытии проекта снимок, разобранный прошлой `PARSER_VERSION`, пересобирается из `files/`. После считывания заметки модели к частям, которых больше нет, удаляются (`glossary::prune_notes`). Списки персонажей и терминов отмечают записи для описания моделью группой (`describe_entries`). Кнопка «Шрифты» в карточке мода (`src/lib/FontPanel.svelte`, помощники в `src/lib/font-preview.ts`) показывает шрифты игры без кириллицы и ставит замены: `FontService` (`fonts/`: разбор `cmap`, замены в `font_replacements` и `files/`), `GameEngine::fonts` (`engines/renpy/fonts.rs`: упоминания в скриптах, шрифт, который перекрывает свой `tl/russian` игры); в мод замена ложится в `tl/russian` под путём исходного шрифта. Окно настроек моделей, открытое из проекта, правит во вкладке «Действия» и настройки этого проекта (`project_llm_actions`). Стартовый экран меняет папку игры проекта. Кнопка «Исходник» у сцены в таблице и номер строки у реплики открывают текст файла снимка (`src/lib/SourceViewer.svelte`, подсветка в `renpy-highlight.ts`): `ScanService::source`, `GameEngine::source_text` (`.rpyc` декомпилируется), команда `source_file`. Глубина чтения для описаний одна на приложение (`reading_depth` в app.db, `ReadingDepthRepo`, `ReadingDepth::load`, максимум может быть без предела; блок `src/lib/ReadingDepthSettings.svelte` с числовыми полями во вкладке «Действия» окна настроек моделей; число частей для одной сцены по умолчанию считает `partsFor` в `src/lib/reading-depth.ts`). Процент перевода считает `src/lib/progress.ts`: 100% только у полностью переведённого. Вид «Вся игра» в переключателе видов таблицы (`src/lib/GamePage.svelte`, состояние цепочки `GameRun` в `src/lib/game-run.svelte.ts` живёт в `Workspace.svelte`, помощники в `src/lib/game-run.ts`) запускает шаги модели по всей игре одной очередью: разбор сцен, переводы глоссария (термины, подписи, токены принимаются без отбора, имена «Авто» первым вариантом или «Ручной выбор» с отбором `src/lib/NamePicks.svelte` и продолжением), описания персонажей и терминов, описания сцен, перевод, вычитка. Сводка и итог по шагам: `GameRunService` (`game_run/`, команды `game_overview`, `run_game`, `write_names`); цепочка занимает место один раз (`RunChain`), сервисы действий принимают `RunHost` и пишут свои строки `llm_runs`. Продолжение после остановки держат отметки `analyzed_parts` (разбор пропускает прочитанные части везде) и `reviewed_lines` (вычитка цепочки берёт только невычитанное). Кнопка «Сбросить всё» на этой странице (`GameRunService::reset`, команда `reset_game`, `clear` у репозиториев) возвращает проект к состоянию после считывания: переводы с историей, описания, заметки, отметки, весь глоссарий и запуски удаляются, снимок и настройки остаются. Код 1.0 удалён целиком.

Проектная документация лежит не в репозитории, а в Docmost: страница «Структура приложения» (слои, классы, сценарии), раздел «Хранилище 2.0» (схемы app.db, project.db, cache.db) и страница «Правила интерфейса» (цвета, текст, отступы, элементы окна 2.0: новый экран собирается из них). Код следует им. Если решение меняется, сначала обновляется страница.

## Команды

Из корня проекта:

```bash
npm install
npm run tauri dev
npm run tauri build
npm run check
node --test tests/*.test.mjs
node --test --test-name-pattern="focused mode" tests/scene-graph.test.mjs
```

Скрипта `npm test` нет. Тесты импортируют `.ts` напрямую, поэтому нужен Node с нативной загрузкой TypeScript.

Из `src-tauri`:

```bash
cargo test --lib
cargo test --lib test_corrupt_segment_sizes_do_not_overflow
cargo test --lib -- --ignored
cargo test --lib export_bindings
cargo clippy --lib --tests
```

`export_bindings` пересобирает `src/lib/bindings.ts`: типы и вызовы команд для окна из `commands()` в `lib.rs` (`tauri-specta`). После правки команд или их типов файл пересобирают и коммитят вместе с ними. `build.rs` передаёт манифест Windows (`windows-app-manifest.xml`) компоновщику для всех целей: без Common Controls v6 тестовые `.exe`, которые тянут код окна, падают с `STATUS_ENTRYPOINT_NOT_FOUND`.

Тесты с `#[ignore]` в `engines/renpy` работают на реальных играх и берут пути из переменных окружения: `TRANSLATOR_TEST_TRANSLATED_GAME`, `TRANSLATOR_TEST_RPA_GAME`, `TRANSLATOR_TEST_CHARACTERS_GAME`, `TRANSLATOR_TEST_RPA2_ARCHIVE`, `TRANSLATOR_TEST_FRAMED_ARCHIVE`, `TRANSLATOR_TEST_TL_DIR`, `TRANSLATOR_TEST_PACKED_TL_GAME`, `TRANSLATOR_TEST_MOD_GAME` (сборка мода с переводом каждой реплики, тест в `engines/renpy/modpack.rs`), `TRANSLATOR_TEST_RESCAN_GAME` (корень игры: перевод каждой реплики переживает пересборку и повторное считывание, номер строки каждой реплики указывает на неё в исходнике, тесты в `scan/service.rs`). Без переменной такой тест ничего не проверяет и проходит. `TRANSLATOR_RPYC_PROBE_DIR` включает запись архивов для проверки скомпилированных скриптов настоящим движком.

## Устройство Rust

Папки по фичам, слои это файлы внутри фичи (`model.rs`, `repo.rs`, `service.rs`), в каждой папке `mod.rs`:

- `projects/`: список проектов, создание, открытие, смена папки игры, удаление.
- `scan/`: снимок игры в project.db, переходы `edges` (`EdgeRepo`, пересборка из `files/` в `ScanService::refresh_edges`), сопоставление реплик после повторного считывания (`matching.rs`), «Пропавшие».
- `graph/`: граф сцен для окна: сцены текущего снимка с прогрессом (`GraphRepo`) и переходы. Переходы собирает движок (`GameSnapshot::edges`, `GameEngine::read_edges`), у Ren'Py это `scene_edges` в `scenes.rs`; после правки сборки поднимается `EDGES_VERSION` в `engines/renpy/mod.rs`.
- `llm/`: провайдеры и профили, действия и их настройки, цель запроса (`LlmTarget`), HTTP (`LlmClient`), запуск (`LlmRun`, `RunSlot`).
- `translation/`: перевод и редактура реплик: пакеты, промпт, разбор ответа, черновики и история.
- `glossary/`: говорящие и связи с персонажами, персонажи, термины, токены, описания сцен, заметки модели, `NameKey`.
- `name_rules/`, `fonts/`, `export/`: правила имён, замены шрифтов, сборка и установка мода.
- `game_run/`: цепочка «Вся игра»: сводка по шагам и шаги по очереди внутри одной `RunChain`, без своей логики действий.
- `engines/`: порт `GameEngine` и типы снимка. `engines/renpy/` это адаптер Ren'Py: `rpa` (архивы RPA-2.0 и 3.0), `rpyc` (декомпиляция), `rpyc_writer` (компиляция `.rpyc` без игры), `pickle`, `script` (разбор `.rpy`) и `graph` перенесены из 1.0. Считывание (`snapshot.rs`) идёт в два шага: `collect_folder` кладёт нужные файлы в `FileStore` как есть (скрипты, `tl/russian`, картинки перевода, шрифты; файл на диске важнее архива, архивы с конца алфавита, `.rpyc` рядом со своим `.rpy` не нужен), `analyze` собирает снимок только из `FileStore`, поэтому пересборка без папки игры идёт тем же путём. Реплики берутся из `tl/russian`, если он есть, иначе из скриптов. Ключ реплики это JSON `LineKey`: `Block` по `id`, `Strings` и `Loose` (вне меток) с путём файла, `Script` по метке. Порядок сцен по сюжету в `scenes.rs`.
- `storage/`: `Database` и обёртки `AppDb`, `ProjectDb`, `CacheDb`. Миграции app.db и project.db (`migrations.rs`) это SQL-файлы `storage/schema/<база>/NNNN_<имя>.sql` в явном списке `APP` и `PROJECT`, история применённых шагов лежит в таблице `schema_migrations`. Новый шаг добавляется в конец, выпущенный шаг не меняется. cache.db без миграций: `schema/cache.sql` и `CACHE_VERSION`. `files.rs` это `FileStore`, `secrets.rs` это `SecretStore`, `state.rs` это `AppState` и `OpenProject`, `common.rs` это общие типы и ошибки.

### Правила слоёв

- **Ядро без ввода-вывода.** Модели держат поля приватными и проверяют правила сами, неверные данные из базы дают `ValidationError`, а не панику. Чистые функции (пакеты, промпты, разбор ответа, сопоставление) тоже в ядре.
- **Репозиторий** это `struct XRepo<'c> { conn: &'c Connection }` на одну операцию: только SQL над своими таблицами, без транзакций и правил. Трейтов у репозиториев нет, тесты идут на настоящей SQLite.
- **Сервис** задаёт порядок шагов, открывает транзакции (`Database::read`, `Database::write`) и делает ввод-вывод. Транзакция короткая: ответ модели и чтение игры идут вне её. Одна транзакция работает с одной базой, `ATTACH` не используется.
- **Ответ модели** пишется только в реплику, которая осталась в том виде, в каком ушла модели (`Draft.sent`).
- **Запуск модели** один за раз во всём приложении: место занимает `LlmRun::begin` через `RunSlot`.
- **Ключи API** знает только `SecretStore`. `ApiKey` без `Debug` и `Serialize`.
- **Файлы в базе не хранятся:** содержимое лежит в `projects/<id>/files/<sha256>`, в базе только сведения о файле.
- **Ren'Py только в `engines/renpy`.** Хранилище и общий код не опираются на раскладку папок движка. Ключи контейнеров, реплик и говорящих база хранит как непрозрачные строки.
- **Совместимости с 1.0 нет:** данные 1.0 не читаются и не переносятся.

## Главные инварианты

- **Панику в Rust нельзя допускать на данных игры и базы.** В релизе `panic = "abort"`, поэтому паника закрывает приложение. Файлы игр недоверенные: разбор возвращает `Err`, архивы проверяются на выход за пределы папки (`safe_output_path`), `unwrap` на значениях из базы запрещён.
- **CSP действует только в сборке.** В `tauri dev` страница грузится с dev-сервера напрямую, поэтому правила из `tauri.conf.json` проверяются на `tauri build`. Интерфейс не обращается к сети сам: запросы к нейросети идут из Rust.
- **Вызовы JS API Tauri**, кроме собственных команд, требуют разрешений в `src-tauri/capabilities/default.json`: `core:default` и `opener:default` покрывают не всё.
- **Если меняется вывод декомпилятора или разбора**, поднимается `PARSER_VERSION` в `engines/renpy/mod.rs`: разбор в cache.db и снимок пересобираются из `files/`. `CACHE_VERSION` в `rpa.rs` остался от дискового кэша 1.0 (`refresh_script_cache`) и уйдёт вместе с ним.

## Соглашения

- Комментарии и сообщения для пользователя пишутся на русском.
- Команды Tauri лежат в `<фича>/commands.rs`, помечены `#[specta::specta]`, регистрируются в `commands()` в `lib.rs` и возвращают `Result<_, String>`. Работа идёт через `state::blocking`: вне потока окна, а `AppError` становится текстом. Типы для окна это DTO с `specta::Type`, `i64` в них помечается `#[specta(type = specta_typescript::Number)]`. В окне ошибка команды приходит исключением со строкой (`ErrorHandlingMode::Throw`).
- Стили окна 2.0 берутся из `src/app.css` (подключён в `src/routes/+layout.svelte`): токены цветов на `:root` и общие классы `.btn`, `.icon-button`, `.input`, `.field`, `.segmented`, `.banner`, `.card`, `.badge`, `.error-text`, `.spin`. Компонент не пишет цвет числом и не копирует вид общих элементов. Значения и правила текста на странице «Правила интерфейса» в Docmost: новое значение сначала там.
- Сообщения коммитов следуют Conventional Commits на английском.
