# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Translator: настольное приложение на Tauri 2 (Rust) и Svelte 5 для перевода игр на Ren'Py на русский, с графом сцен, глоссарием и локальными LLM (LM Studio, Ollama). Парсер спрятан за трейтом `GameParser`, но реализован только Ren'Py.

## Команды

Из корня проекта:

```bash
npm install
npm run tauri dev
npm run tauri build
npm run check
node --test tests/*.test.mjs
node --test --test-name-pattern="focused mode" tests/scene-graph.test.mjs
```

Скрипта `npm test` нет. Тесты импортируют `.ts` напрямую, поэтому нужен Node с нативной загрузкой TypeScript.

Из `src-tauri`:

```bash
cargo test --lib
cargo test --lib test_saved_edits_survive_line_shifts
cargo test --lib -- --ignored
cargo clippy
```

Тесты с `#[ignore]` работают на реальных играх и берут пути из переменных окружения: `TRANSLATOR_TEST_TRANSLATED_GAME`, `TRANSLATOR_TEST_RPA_GAME`, `TRANSLATOR_TEST_CHARACTERS_GAME`, `TRANSLATOR_TEST_RPA2_ARCHIVE`, `TRANSLATOR_TEST_FRAMED_ARCHIVE`, `TRANSLATOR_TEST_TL_DIR`, `TRANSLATOR_TEST_PACKED_TL_GAME`. Без переменной такой тест ничего не проверяет и проходит. `TRANSLATOR_RPYC_PROBE_DIR` включает запись архивов для проверки скомпилированных скриптов настоящим движком.

## Архитектура

Интерфейс почти целиком находится в `src/routes/+page.svelte`. Это SPA без SSR. Команды Tauri объявлены в `src-tauri/src/lib.rs` и регистрируются в `generate_handler!`. Вызовы JS API Tauri, кроме собственных команд, требуют разрешений в `src-tauri/capabilities/default.json`: `core:default` и `opener:default` покрывают не всё.

### Главные инварианты

- **Папка игры только для чтения.** Всё пишется в `%LOCALAPPDATA%\TranslatorApp\projects_cache\<имя>_<хэш пути>`: `scripts/` (скрипты из RPA), `translations/*.json` (правки), `glossary.json`, `scene_notes.json` (заметки модели по частям сцен), `exports/`, `unpacked/`. Вывод в игру запрещает `ensure_output_outside_game`.
- **Панику в Rust нельзя допускать на данных игры.** В релизе `panic = "abort"`, поэтому паника закрывает приложение. Файлы игр считаются недоверенными: разбор возвращает `Err`, а архивы проверяются на выход за пределы папки (`safe_output_path`).
- **Путь оценивается относительно корня игры.** Папка `tl` может встретиться и выше игры, поэтому файл перевода определяют `is_translation_path` и `tl_relative_name`, а не подстрока пути.
- **CSP действует только в сборке.** В `tauri dev` страница грузится с dev-сервера напрямую, поэтому правила из `tauri.conf.json` проверяются на `tauri build`. Интерфейс не обращается к сети сам: запросы к нейросети идут из Rust.
- **Язык задан константой.** `TL_LANG` в `lib.rs` равен `russian`, то же значение записано в `SourceViewerModal.svelte`.

### Поток данных

1. **Скан** (`scan_game_project`): `refresh_script_cache` складывает в `scripts/` то, что нельзя прочитать прямо из папки игры: содержимое `.rpa` и `.rpyc` без `.rpy` рядом, декомпилированные в `.rpy`. Как и в движке, скрипт на диске важнее архива, поэтому его копии в кэше нет. Если кэшировать нечего, папка удаляется. Затем собираются персонажи и список файлов: перевод `tl/russian` с диска и из кэша, а если его нет, скрипты из кэша и из папки игры. Прогресс файла с сохранёнными правками считается с их учётом. Папка `_mods` и свой архив `ru_lang.rpa` при этом пропускаются.
2. **Разбор** (`parse_project_file`): `RenpyParser` строит `ScenarioGraph` из файла перевода или оригинала, а структура сцен и переходов берётся из оригинала (`resolve_original_script`, в том числе из кэша). Кнопки экранов дают переходы от сцен, показавших экран, через весь проект (`screen_targets`, `screen_edges`). Результат кэшируется по времени изменения файлов. Текст для нейросети и сцены персонажа в глоссарии (`scenes.rs`) собираются этим же разбором из оригиналов на диске и в кэше (`original_scripts`). У одного героя может быть несколько кодов: `merged` в записи глоссария объединяет их реплики и сцены, а скан не возвращает такие коды отдельными записями. В реплики для модели подставляются значения строковых переменных из скриптов, а запросы ограничены по объёму текста, чтобы уместиться в окно контекста. Термины находятся без модели по всем репликам (`terms.rs`), она только проверяет и переводит кандидатов, а в глоссарий их отбирает пользователь. Итог каждого пакета приходит в окно через `Channel` и может отстать от итога команды, а `cancel_llm_run` останавливает обработку между пакетами. Описание персонажа по заметкам собирается и после остановки чтения.
3. **Правки** (`translation.rs`): игровые файлы не меняются, правки лежат в JSON по ключу `LineKey`. Он не зависит от номера строки: `Block` для блоков `translate`, `Strings` для `old`, `Script` для оригинальных скриптов. Старые ключи-массивы переносятся при загрузке.
4. **Экспорт** (`build_mod_archive`):
   - В мод входит весь перевод игры: файлы `tl/<язык>` с диска и из архивов (`packed_translation_files`) вместе с картинками и шрифтами. Поэтому мод работает и в копии игры без этого перевода.
   - Правки файлов `tl/<язык>` подставляются в копии этих файлов.
   - Остальные правки становятся строковыми переводами в `translator_saved_strings.rpy`, потому что `id` блоков `translate` вычисляет сам Ren'Py.
   - `translator_language.rpy` включает язык, если в игре нет такого пункта.
   - Всё компилируется и упаковывается в `ru_lang.rpa`, потому что из архивов Ren'Py читает только `.rpyc`.
   - Файлы `tl/russian` на диске Ren'Py читает раньше архива. Перекрывать их не нужно: чтобы применить мод, такой перевод удаляют.

### Форматы Ren'Py

- `pickle.rs`: декодер и кодировщик Python pickle для индексов RPA и деревьев скриптов. Значения считаются деревьями без ссылок, поэтому глубина ограничена `MAX_PICKLE_DEPTH`, а копии из memo `MAX_MEMO_NODES`. Рекурсивный обход `.rpyc` идёт на потоке с большим стеком (`statements_of`).
- `rpa.rs`: чтение и запись архивов RPA-2.0 и RPA-3.0.
- `rpyc.rs`: декомпиляция в упрощённый `.rpy` только для разбора, не для повторной компиляции игрой. Отступы сохраняют вложенность `menu` и `if`: по ним `parse_script_structure` строит выборы и условия. От экранов остаются только связи: `action` с `Jump`/`Call`/`Show` и `use`, а также `call screen` и `show screen` в сценах. Файлы перевода восстанавливаются точнее (`decompile_translation`): блоки `translate`, строки `old`/`new` и комментарии с оригиналом, найденным по `id`. В `.rpyc` игры `id` не хранятся, их считает `DialogueIdentifiers` так же, как `Restructurer` в движке, поэтому `say_code` повторяет `Say.get_code`. Оператор, который нельзя восстановить, записывается как `<Класс>`, чтобы правка такого файла остановила сборку. Если вывод декомпилятора меняется, нужно поднять `CACHE_VERSION` в `rpa.rs`, иначе останется старый кэш.
- `rpyc_writer.rs`: компилятор `.rpyc` без запуска игры. Формат определяется по файлам движка (`ScriptFormat::detect`), поддерживаются три раскладки `AstLayout`. Компилируются только строковые переводы, блоки `translate` с репликами (включая аргументы, атрибуты после `@`, `nointeract` и `with`) и `init python`, остальное останавливает сборку.

### Состояние в памяти

Статические кэши в `lib.rs` (`PARSED_FILE_CACHE`, `SCRIPT_STRUCTURE_CACHE`, `PROJECT_CACHE`) сбрасываются при сохранении правок и очистке кэша. Разобранные реплики (`game_lines`) готовятся в фоне после скана, идут в порядке сюжета (`story_order`) и живут до следующего скана. `find_game_root` определяет корень игры по открытым проектам (`project_roots`), а для остальных файлов по признакам на диске. От него зависит путь к хранилищу правок. Папка данных проекта привязана к пути игры, поэтому после переезда или в новой версии правки и глоссарий переносятся явно (`transfer_project_data`). Запись одного файла или папки сериализуется через `path_lock`.

## Соглашения

- Комментарии и сообщения для пользователя пишутся на русском.
- Команды Tauri возвращают `Result<_, String>`, а работу с диском выполняют в `spawn_blocking`.
- Сообщения коммитов следуют Conventional Commits на английском.
