# Проверка языковых кодов

Новые коды проверяет `LanguageTag::validate_registered` через `language-tags` 0.3.2.
Библиотека включает снимок [реестра IANA](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry)
и проверяет регистрацию языка, письменности, региона и вариантов, а также структуру тега.
Во время работы приложения сеть не нужна. Версия снимка определяется версией зависимости
в `Cargo.lock`; библиотека не публикует дату снимка в своём API.

Для обновления справочника обновить зависимость `language-tags` и `Cargo.lock`, затем
запустить тесты `name_rules` и `glossary`. Генератор данных находится в `scripts` исходников
библиотеки. Список языков вручную не дополняется.

Группы языков (`Scope: collection`, например `grk`, `gem`, `sla`) не допускаются:
для правил произношения нужен конкретный язык. Библиотека не предоставляет Scope,
поэтому список групп генерируется из IANA командой
`pwsh -File src-tauri/scripts/update-language-collections.ps1` и хранится в
`language-collections.txt` с источником и датой снимка. Его следует обновлять вместе
с библиотекой. Макроязыки вроде `zh` остаются допустимыми.

Правила по-прежнему используют строковые ключи (`ja`, `pt-BR`), отдельной таблицы языков нет.
Проверка выполняется при сохранении и импорте правил, запросе черновика и приёме происхождения
от модели. У ответа с неверными кодами есть одна попытка исправления, затем `und` с пояснением.
Зарегистрированные искусственные языки допустимы; пользовательские теги пока не поддерживаются.

Чтение старых записей использует прежний `parse`, без проверки реестра. Это позволяет открыть
проект со старыми неверными кодами и удалить его правила. Автоматической миграции кодов нет:
страна не определяет язык, а некоторые коды совпадают (`se`, `kr`). Реестр проверяет наличие
кода, но не правильность выбора языка для конкретного имени.
